# Plan: AGRI MASSRIDES Admin Dashboard Fixes

## Overview
Fix authentication errors (401/400), RLS violations, database schema mismatches, UI responsiveness issues, and mock data removal for the AGRI MASSRIDES agricultural marketplace admin dashboard.

---

## Issue Analysis

### 1. Authentication Errors (401/400)
- **Root cause**: Edge function `get-admin-dashboard-data` uses service role key to query `user_profiles` but may fail RLS when checking user role
- **AuthContext.tsx**: Looks solid, handles session correctly
- **Edge function**: Uses both service role (for data) and user context (for auth) - needs proper handling

### 2. Database Schema Mismatch
- **Issue**: `orders` table missing `billing_address` column (only has `shipping_address`)
- **Error**: 42703 "column orders_1.billing_address does not exist" in Vesicash monitor
- **Location**: `VesicashPaymentMonitoring.tsx` line 178 joins with `billing_address`

### 3. RLS Policy Issues
- **Inventory**: RLS policies exist but may block service role queries
- **User profiles**: Edge functions need proper role checks using service role

### 4. UI Responsiveness
- **Orders page**: Uses `<select>` for status filter - not mobile-friendly, needs dropdown component

### 5. Mock Data
- **AdminDashboard**: Shows hardcoded "98%" system health, needs real metrics

### Phase 7: Database Schema Comparison

#### 7.1 Create Schema Comparison Script
**File**: `scripts/compare-db-schema.ts` (or inline query)

Purpose: Compare online Supabase database schema with local `database.types.ts` definitions

Comparison Query Approach:
```sql
-- Query to get online DB column definitions
SELECT 
  table_name,
  column_name,
  data_type,
  is_nullable,
  column_default
FROM information_schema.columns
WHERE table_schema = 'public'
ORDER BY table_name, ordinal_position;
```

#### 7.2 Create Comparison Tool
**Implementation Options**:
1. SQL query script to run manually
2. Edge function that returns schema comparison
3. Frontend page showing schema differences

Key comparisons to make:
- **Missing columns**: Columns in local types but not in online DB
- **Extra columns**: Columns in online DB but not in local types
- **Type mismatches**: Different data_type between local and online
- **Nullable differences**: NULL vs NOT NULL mismatches

Output format:
```json
{
  "missingColumns": [{ "table": "orders", "column": "billing_address", "localType": "jsonb" }],
  "extraColumns": [],
  "typeMismatches": []
}
```
